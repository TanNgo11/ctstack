Onboarding CTStack

Dành cho người lần đầu làm Astro, EmDash và Cloudflare. Đọc từ trên xuống mất khoảng 30–40 phút, làm bài tập ở mục 11 thêm 30 phút.

1Bức tranh tổng

Site này là một ứng dụng duy nhất, gồm cả trang web lẫn trang quản trị (CMS), chạy trên hạ tầng Cloudflare. Không có server riêng, không có backend tách biệt.

Astro

Framework dựng trang web. Viết file .astro (HTML + JS chạy ở server), Astro render ra HTML gửi cho browser. Gần giống PHP/Blade/EJS nhưng hiện đại, có component.

EmDash

CMS cắm vào Astro, kiểu WordPress thế hệ mới. Cho mình trang admin /_emdash/admin để nhập dự án và dịch vụ, cùng API để đọc dữ liệu đó trong trang.

Cloudflare Workers

Nơi code chạy. Không phải VPS: code chạy "serverless" trên mạng của Cloudflare, mỗi request gọi 1 lần. Gói free đủ dùng.

D1 + R2

D1 là database SQLite của Cloudflare (lưu nội dung, user, lead). R2 là kho file (lưu ảnh upload), giống S3.

TypeScript

JavaScript có kiểu dữ liệu. pnpm typecheck bắt lỗi trước khi chạy.

pnpm

Trình quản lý package như npm nhưng nhanh và chặt hơn. Dự án này chỉ dùng pnpm.

Một request đi như thế nào

Browser mở /en/projects/abc→ Cloudflare Worker→ EmDash middleware→ File src/pages/[...lang]/projects/[slug].astro→ Query D1→ Render HTML→ Browser

Mọi trang được render ở server, mỗi lần có request (SSR), không build sẵn HTML tĩnh. Nhờ vậy sửa nội dung trong admin là site cập nhật ngay, không cần build lại.

Sơ đồ kiến trúc chi tiết ở overview.html.

2Chạy lần đầu

Cần: Node.js 22+, pnpm (corepack enable hoặc npm i -g pnpm), Git.

pnpm install        # cài package
pnpm dev            # chạy dev server → http://localhost:4321
  1. Mở http://localhost:4321. Lần đầu database trống nên chưa có dự án nào.
  2. Mở link đăng nhập nhanh (chỉ có ở môi trường dev), link này cũng nạp luôn content mẫu:
    http://localhost:4321/_emdash/api/setup/dev-bypass?redirect=/_emdash/admin
  3. Vào admin, xem các mục Projects, Services, Pages, Forms.
  4. Form liên hệ trên DB mới cần tạo lại: chạy node scripts/create-contact-forms.mjs (khi pnpm dev đang chạy). Script tạo form lien-he (vi) và contact (en), form nào có rồi thì bỏ qua. Cũng có thể tạo tay trong Admin → Forms.
Ở local, Cloudflare được giả lập bằng Miniflare: D1 và R2 nằm trong thư mục .wrangler/state. Muốn reset dữ liệu thì tắt server rồi xóa thư mục đó.

3Astro căn bản

Cấu tạo 1 file .astro

Mỗi file có 3 phần: frontmatter (code chạy ở server, nằm giữa 2 dấu ---), template (HTML) và style (CSS chỉ áp dụng cho file đó). Ví dụ rút gọn từ src/components/ServiceCard.astro:

---
// 1. Frontmatter: chạy ở SERVER, không gửi xuống browser
import ServiceIcon from "./ServiceIcon.astro";

interface Props {            // khai báo props nhận vào
  title: string;
  priceFrom?: string;
}
const { title, priceFrom } = Astro.props;
---
<!-- 2. Template: HTML, dùng {biến} để in giá trị -->
<article class="service-card">
  <ServiceIcon name="globe" />
  <h3>{title}</h3>
  {priceFrom && <p>Từ {priceFrom}</p>}   <!-- điều kiện -->
</article>

<style>
  /* 3. CSS chỉ áp dụng cho component này (scoped) */
  .service-card { padding: 2rem; }
</style>
  • Lặp danh sách: {items.map((i) => <li>{i}</li>)}, giống JSX của React.
  • Dùng component: import rồi viết như thẻ HTML <ProjectCard title="..." />.
  • <slot /> là chỗ đặt nội dung con, dùng trong layout Base.astro.
  • Muốn CSS ảnh hưởng HTML do component khác sinh ra thì bọc selector bằng :global(...).
  • Code trong <script> (không có is:inline) mới chạy ở browser. Frontmatter không bao giờ chạy ở browser.

Routing theo tên file

File trong src/pages/ tự thành URL:

FileURL
src/pages/[...lang]/index.astro/ và /en
src/pages/[...lang]/services.astro/services và /en/services
src/pages/[...lang]/projects/[slug].astro/projects/<slug>, /en/projects/<slug>
src/pages/404.astroTrang lỗi 404
  • [slug] là tham số động, đọc bằng Astro.params.slug.
  • [...lang] là tham số "rest", có thể rỗng. Mình dùng nó cho ngôn ngữ (xem mục 5).
  • Chỉ page mới được return Astro.redirect(), return Astro.rewrite() hoặc Response. Component thì không.

Layout

Mọi trang bọc trong <Base title="...">...</Base> (src/layouts/Base.astro). Base lo phần <head>, SEO, menu, nút đổi ngôn ngữ, footer và nút sáng/tối.

4EmDash (CMS)

Khác nhiều CMS khác, schema (cấu trúc dữ liệu) nằm trong database, không nằm trong code. Lúc đầu schema được tạo từ file seed/seed.json, sau đó có thể sửa trong admin.

Khái niệm

Khái niệmLà gìTrong dự án
CollectionLoại nội dung, giống 1 bảngprojects, services, pages
FieldCột của collectiontitle, featured_image, results…
Entry1 bài/1 dòng dữ liệuDự án "Website chuỗi cà phê"
SlugPhần URL của entrywebsite-chuoi-ca-phe
Locale / TranslationMỗi ngôn ngữ là 1 entry riêng, liên kết thành nhóm bản dịchBản vi + bản en
Portable TextRich text lưu dạng JSON (không phải HTML)Field content (case study)
RepeaterDanh sách các dòng conresults, gallery, features
SeedFile khởi tạo schema + content mẫuseed/seed.json
PluginMở rộng CMS@emdash-cms/plugin-forms (form liên hệ)

Đọc dữ liệu trong trang

import { getEmDashCollection, getEmDashEntry } from "emdash";

// Danh sách: dịch vụ tiếng Việt, sắp theo sort_order
const { entries, error } = await getEmDashCollection("services", {
  locale: "vi",
  orderBy: { sort_order: "asc" },
  limit: 50,
});

// 1 entry theo slug
const { entry, error } = await getEmDashEntry("projects", slug, { locale: "en" });

entry.id          // = slug, dùng làm URL
entry.data.id     // = ID thật trong DB (ULID), dùng khi gọi API khác
entry.data.title  // các field nằm trong entry.data

Hiển thị

import { Image, PortableText } from "emdash/ui";

<Image image={entry.data.featured_image} />   <!-- ảnh là OBJECT, không phải string -->
<PortableText value={entry.data.content} />   <!-- render rich text -->
<h1 {...entry.edit.title}>{entry.data.title}</h1>   <!-- cho phép sửa trực tiếp khi admin đang login -->

Seed chạy khi nào

  • DB trống + request đầu tiên: EmDash tạo schema từ seed.
  • Content mẫu chỉ được nạp khi chạy setup wizard (hoặc link dev-bypass) và chọn nạp content.
  • Sửa seed.json không ảnh hưởng DB đang có dữ liệu. Muốn áp lại ở local thì xóa .wrangler/state.
EmDash có MCP server ở /_emdash/api/mcp: AI agent (Claude…) có thể đọc và ghi content qua đó. Đây là lý do chọn EmDash (Phase 3).

5Song ngữ vi/en

Tiếng Việt là mặc định, không có tiền tố URL. Tiếng Anh nằm dưới /en. Có 2 loại chữ, mỗi loại dịch một cách:

Chữ cố định trên giao diện

Menu, nút, tiêu đề mục… nằm trong src/i18n/ui.ts, có 2 object vi và en. Thiếu key tiếng Anh là TypeScript báo lỗi.

Nội dung trong CMS

Dự án, dịch vụ, trang: mỗi thứ có 1 entry vi + 1 entry en, liên kết qua mục Translations trong admin.

Mọi page đều mở đầu như sau:

const lang = langFromParam(Astro.params.lang);  // "" → "vi", "en" → "en", khác → null
if (!lang) return Astro.rewrite("/404");
const t = useTranslations(lang);

t("nav.projects")                  // "Dự án" hoặc "Projects"
localizePath("/projects", lang)    // "/projects" hoặc "/en/projects"
Đừng viết link cứng kiểu href="/en/contact". Luôn dùng localizePath().

Binding là "tên biến" để code truy cập tài nguyên Cloudflare. Code không cần URL hay mật khẩu DB, chỉ cần binding DB.

Deploy lần đầu

pnpm exec wrangler login     # đăng nhập tài khoản Cloudflare (mở browser)
pnpm run deploy              # build + deploy, tạo D1/R2 nếu chưa có
pnpm exec wrangler secret put EMDASH_ENCRYPTION_KEY   # dán giá trị trong .env

Sau đó vào https://ctstack.<tài-khoản>.workers.dev/_emdash/admin để chạy setup wizard. Production dùng DB riêng, trống ban đầu, không dùng chung với local.

8Công thức thường gặp

Thêm 1 dòng chữ mới trên giao diện
  1. Trong src/i18n/ui.ts, thêm key vào object vi, ví dụ "home.badge": "Phản hồi trong 24h".
  2. Thêm cùng key vào object en: "home.badge": "Reply within 24h".
  3. Trong trang: {t("home.badge")}.
  4. pnpm typecheck.
Thêm 1 dự án thật
  1. Admin → Projects → New. Điền bản tiếng Việt, tick featured nếu muốn hiện ở trang chủ, rồi Publish.
  2. Trong entry đó mở Translations → tạo bản en, dịch, rồi Publish.
  3. Theo quy tắc trong content-guide.md: không bịa số liệu.
Thêm field mới cho dự án (ví dụ "duration")
  1. Admin → Content Types (Schema) → Projects → thêm field duration (string). Làm vậy thì DB hiện tại có field ngay.
  2. Thêm cùng field vào seed/seed.json để DB mới (production, máy khác) cũng có.
  3. Restart pnpm dev để sinh lại type (emdash-env.d.ts), khi đó entry.data.duration có gợi ý kiểu.
  4. Hiển thị trong projects/[slug].astro, thêm nhãn vào ui.ts (vi + en).
  5. Cập nhật content model trong docs/architecture.md.
Thêm 1 trang mới (ví dụ /faq)
  1. Tạo src/pages/[...lang]/faq.astro, copy phần mở đầu (lang, t) từ services.astro.
  2. Bọc nội dung trong <Base title={...}>.
  3. Thêm link vào mảng nav trong Base.astro + key dịch trong ui.ts.
  4. Kiểm tra cả /faq và /en/faq.
Đổi màu thương hiệu 
/* src/styles/theme.css — light-dark(màu sáng, màu tối) */
:root {
  --color-brand: light-dark(#2563eb, #60a5fa);
}
Thêm thư viện

pnpm add ten-thu-vien. Package mới phát hành dưới 24 giờ sẽ bị chặn (cấu hình trong pnpm-workspace.yaml). Đó là cơ chế bảo vệ, không phải lỗi.

10Làm việc với AI (vibe code)

Repo đã chuẩn bị sẵn để AI hiểu dự án:

  • AGENTS.md: luật chính. Codex, Cursor, Claude đều đọc file này. CLAUDE.md import lại nó.
  • .agents/skills/ (và .claude/skills/, là symlink tới cùng chỗ): skill chính thức của EmDash dạy AI dùng API đúng.
  • .mcp.json: nối AI với tài liệu EmDash online để tra API.
  • docs/: kiến trúc, roadmap, quyết định, quy tắc content.
  • plans/: mỗi tính năng 1 plan. mockup/: ảnh thiết kế + brief cho từng tính năng.

Quy trình 1 tính năng

Chọn việc trong docs/roadmap.md→ Bảo AI viết plans/NNN-*.md→ Duyệt plan→ (UI) có mockup→ AI code→ typecheck + build + xem vi/en→ commit

Branch và chạy nhiều session song song

  • Mỗi session (người hoặc AI) làm trên 1 branch, trong worktree riêng. Không cho 2 session chung 1 worktree.
  • Chia việc thành bước nhỏ (design system → header/footer → từng trang), mỗi bước 1 commit.
  • Trước khi merge vào main: pnpm typecheck 0 lỗi và pnpm build chạy qua.
  • Merge vào main sau mỗi bước, rồi kéo main về các branch khác sớm để không lệch nhau.
  • File dùng chung (theme.css, Base.astro, ui.ts, seed.json): mỗi lúc chỉ 1 branch được sửa.
  • UI: chụp màn hình 390px và 1440px, đặt cạnh mockup, khớp rồi mới tick trong plan.
  • Secret (API key…): local để trong .env/.dev.vars, production dùng wrangler secret put. Không bao giờ ghi vào wrangler.jsonc hay commit.
Prompt mẫu: "Đọc AGENTS.md và plans/001-ui-redesign.md, làm task Header + footer theo mockup/00-design-system và mockup/01-home. Xong thì chạy typecheck, build và kiểm tra /, /en."

11Bài tập 30 phút

Làm lần lượt để quen tay. Làm xong thì git checkout . nếu không muốn giữ thay đổi.

  1. Chạy site: pnpm dev, đăng nhập bằng link dev-bypass, bấm qua mọi trang, đổi ngôn ngữ.
  2. Sửa content: trong admin đổi giá dịch vụ "Website doanh nghiệp", reload trang /services để thấy thay đổi, không cần build.
  3. Sửa chữ UI: đổi "home.title" trong ui.ts (cả vi và en), xem trang chủ tự reload.
  4. Đổi màu: đổi --color-brand trong theme.css sang màu cam, bật tắt chế độ sáng/tối ở footer.
  5. Đọc 1 page: mở src/pages/[...lang]/projects/[slug].astro, tìm chỗ: lấy lang, query entry, xử lý 404, lấy bản dịch, render.
  6. Gửi form: vào /contact, gửi thử, rồi xem ở Admin → Forms → Submissions.
  7. Kiểm tra: pnpm typecheck và pnpm build.
